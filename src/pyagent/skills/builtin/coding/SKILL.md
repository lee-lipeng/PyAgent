# 代码编写技能

当用户要求编写、修改或调试代码时，遵循以下原则。

## 工作流程

1. **理解需求**：仔细阅读用户的请求，确认要修改的文件和功能。
   不确定时先问用户，不要猜测。
2. **阅读现有代码**：先用 `read_file` 工具阅读相关文件，理解上下文和代码风格。
3. **制定方案**：简述修改方案，确认方向正确后再动手。
4. **执行修改**：用 `edit_file` 做精确替换，或用 `write_file` 创建新文件。
5. **验证结果**：用 `run_bash` 执行测试或编译，确认修改无误。

## 编辑原则

- **先读后改**：修改前必须先阅读目标文件，确保 `old_string` 在文件中唯一出现。
- **最小改动**：优先用 `edit_file` 做小范围修改，避免重写整个文件。
- **保持风格**：遵循项目现有的代码风格、命名约定和格式化规则。
- **中文注释**：添加适当的中文注释解释"为什么"，而非"做了什么"。
  拒绝 AI 味的冗余注释（如 `# 定义一个变量`）。
- **不要猜测**：如果不确定 API 用法或类型，先搜索代码库或查阅文档。

## 验证清单

- [ ] 代码能通过编译/语法检查
- [ ] 相关测试通过（如有）
- [ ] 没有引入新的 lint 警告
- [ ] 修改符合用户预期
